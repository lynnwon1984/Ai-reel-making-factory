# 分镜生成 A/B 实验 v0.2

日期：2026-11-04

## 结论先行

在 EP1、EP4、EP6 三集真实对照中，规则分块 + 云端镜头计划 JSON + 本地编译/修复/裁决的链路，已经可以稳定生成结构合法、台词无漂移、宽景对白受控的分镜稿。它比整稿提示词更适合继续进入流程三实验，但还不能直接替换现有正式流程。

目前没有解决的是**时长膨胀**：新引擎仍比流程二的纯规则估时多约 48%–87%，因此一集原料经常需要裁决成两集，且可能出现一个短集。这个差值不能靠硬压时长解决，下一步必须把“故事估时 → 分镜内容预算”的换算标定清楚。

## 时长裁决

| 集 | 新引擎总时长 | 裁决结果 |
| --- | ---: | --- |
| EP1 | 143s | 2 集：1 个合格，1 个短集 |
| EP4 | 178s | 2 集：均在 75–105s |
| EP6 | 123s | 2 集：1 个合格，1 个短集 |

裁决器只允许在完整 shot 边界切分，不删源块、不拆动作。短集必须明确展示给用户，不能伪造为“通过”。

## 本轮修复

1. **人物行不再静默丢失**：命令行渲染也保留源人物行，不再依赖调用方先跑 `rebuildCast()`。
2. **人物表有双层来源**：即使源人物行缺失，也会从台词说话人建立已知人物表。
3. **群体泛称确定性归并**：例如“村民 / 年轻女子 / 小孩”并入“村民群像”，“弟子们”展开为“男弟子、女弟子”。
4. **台词宽景别修正**：含台词的 WS/FS/EWS 自动收为 MCU；多人群像场景允许受控的一处 MS。
5. **内容补足后再裁决 shot 上限**：本地按内容预算延长 Clip 后，若 shot 超过 15 秒，会在 Clip 边界继续拆成两个合法 shot。
6. **断点恢复只复用合格块**：有结构高问题的落盘块不会被当成完成品；会带着原计划和错误清单继续定点修复。
7. **基线格式归一化**：去掉模型自带的代码围栏和重复集标题，避免把单集误判为两集。
8. **传输稳定性**：网络失败自动重试；本地模型代理增加 10 分钟上游超时。

## 当前判断

有利证据：

- 台词由 `sourceBlockIds` 回填，三集均做到 100% 覆盖，未发现改写。
- 宽景别承载对白的问题被明显压制。
- 新引擎的 shot 数更接近内容密度，没有基线那种“全靠碎片化切 shot 制造节奏”的问题。
- 所有计划块覆盖全部源块，没有漏块或重复引用。
- 本地规则把“能不能交付”变成了可重复判断，不再依赖模型自称完成。

仍需警惕：

- 当前 token 成本约为基线的 2.7–3.7 倍，进入正式产品前必须做缓存、减少无效首稿和按块难度动态选模型等成本优化。
- 新引擎并不是“模型一次就正确”。分块、重试、别名归并、时长预算和 shot 拆分都是必要环节。
- 镜头种类更多不等于导演质量更高，必须人工看动作闭环、视轴、反应镜头和钩子。
- 分镜内容预算天然高于流程二剧情估时，不能把流程二的 75–105 秒直接当作分镜稿最终时长承诺。

4. 达到人工质量门槛后，再在流程三增加“实验引擎”开关；暂不替换现有整稿模式。
