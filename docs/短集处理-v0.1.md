# 短集处理 v0.1

日期：2026-11-05

## 目标

当分镜时长裁决出现短集时，不只报告“69 秒低于 75 秒”，而是给出可执行的下一步：

1. 与相邻集重新分配镜头边界；
2. 与相邻集合并；
3. 补回真实内容；
4. 明确接受短集并记录理由；
5. 退回流程二或内容修改。

原则：

- 不自动拉长镜头凑时长；
- 不删除既有内容；
- 不伪造通过；
- “接受短集”必须显式记录。

## 关键约束

两集都达到下限，需要：

```text
相邻两集总时长 ≥ 75 + 75 = 150 秒
```

因此：

```text
78 + 69 = 147 秒
```

无论镜头边界怎么移动，都不可能让两集同时达到 75 秒。

在这个例子中：

- 重新分界无解；
- 合并为 147 秒会超过 105 秒上限；
- 至少需要补回 6 秒真实内容；
- 或者创作者明确接受 69 秒短集。

## 选项优先级

### 1. 与相邻集合并

只有合并后不超过 105 秒才可用。

适用：

```text
70 + 25 = 95 秒
```

### 2. 与相邻集重新分配

只有相邻两集总时长足以让两集都落进窗口时才可用。

适用：

```text
70 + 90 = 160 秒
```

如果存在镜头边界能切成：

```text
80 + 80
```

系统会给出这个候选。

### 3. 补回真实内容

当重分界和合并都不可用时，计算最低缺口。

```text
69 秒短集 → 至少补 6 秒真实内容
```

补的内容必须来自剧本、反应、被省略动作或有效镜头，不能用空镜、慢放、重复镜头硬凑。

### 4. 明确接受短集

可以把某一集标为 `accepted_short`，但必须带理由，例如：

- 故意停在强钩子上；
- 下一集需要独立开场；
- 制作方明确接受 69 秒。

### 5. 退回上游

如果内容无法补、短集又不可接受，退回流程二重新划分场景边界，或回到剧本内容层处理。

## 实际 147 秒样本

旧版实验结果：

```text
第1集 78 秒
第2集 69 秒
总计 147 秒
```

系统结论：

```text
重分界：不可行
合并：不可行
补内容：至少 6 秒
推荐：补回真实内容
```

这比简单提示“第二集偏短”更明确。

## 当前 160 秒样本

按官方动作规则重跑后：

```text
第1集 81 秒
第2集 79 秒
总时长 160 秒
```

两集都在 75–105 秒窗口内，无需短集处理。

## 实现

- `src/episode-resolution.js`
- `buildEpisodeResolutionPlan(arbitration)`
- `acceptShortEpisode(plan, episodeNo, reason)`

第二项用于显式接受短集，并把该集从待处理清单中移除。

## 测试覆盖

- 78 + 69：正确判断重分界无解，推荐补 6 秒；
- 70 + 90：找到 80 + 80 的可用重分界；
- 70 + 25：优先建议合并为 95 秒；
- 接受短集：状态改为 `accepted_short` 并保存理由。
