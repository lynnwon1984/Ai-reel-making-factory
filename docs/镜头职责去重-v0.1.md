# 镜头职责去重 v0.1

日期：2026-11-05

## 目标

抓两类问题：

1. 同一个动作被正面、侧面、特写重复拍，但状态没有变化；
2. 两个 shot 的职责都是“震惊”“警告”“看证据”，后一镜没有增加信息、压力、关系或后果。

不自动删除镜头，只报告，交给人或定点修复决定。

## 判定信号

每两个 shot 比较：

- `purpose`
- `stateChange`
- `endState`
- 所有 Clip 的 `visualAction`
- `storyFunction`
- `cast`
- `sourceBlockIds + actionUnitIds`

使用字符二元组 Jaccard 相似度，保持确定性、可重复。

## 高风险：直接重复

以下任一成立即报高：

- 两个 shot 引用了同一个动作微单元或源块；
- `purpose` 归一化后完全相同；
- `stateChange` 归一化后完全相同；
- 所有 Clip 的可见动作描述完全相同。

含义：

> 同一内容确实被拍了两遍，除非有明确的冲击重复设计，否则应合并或删除。

## 中风险：高度相似

以下任一成立报中：

- 职责相似度 ≥ 72%；
- 同故事功能下，动作相似度 ≥ 78%、状态变化 ≥ 50%、终点 ≥ 45%；
- 两个都是反应镜，动作相似度 ≥ 70%，人物重叠 ≥ 50%。

含义：

> 后一镜可能只是换角度重复，也可能补充了新信息；必须人工或定点修复确认。

## 合法反应例外

以下情况不判重复：

- 前一镜是“看见危险并震惊”；
- 后一镜是“转头质问师傅”；
- 两镜人物相同，但后一镜出现新判断、新决定或新关系变化。

也就是说，反应本身可以连续，但情绪必须转成新的行动、信息或后果。

## 实现

- 文本相似：`src/text-similarity.js`
- shot 审计：`src/scene-engine.js` 的 `auditShotResponsibilities()`
- 旧 Clip 级雷同检查：`src/qc-engine.js`

Schema v2/v3 的分镜规划在 `validateScenePlan()` 中自动执行 shot 级职责去重。

## 测试覆盖

- 同职责、同动作、同终点，只换角度：高风险；
- 重复引用同一动作：高风险；
- 反应后出现新判断和新行动：不误报；
- 现实现有 23 shot / 5 shot 样本：零误报。

## 局限

这是文本和结构相似度，不是语义理解。

仍可能出现：

- 两段完全不同的文字描述同一种重复动作；
- 同一句“震惊”在不同情境中其实是新信息；
- 有意设计的冲击重复被误报。

因此：

- 高风险必须处理；
- 中风险只提示；
- 不能自动删除。
