# 当前任务：建立原文事实账本

把输入原文拆成最小的叙事事实单元 `S###`，为后续改编提供可追溯依据。你只做提取、核对和风险标注；不设计场景，不写对白，不评价文学质量。

## 输入

```text
[SOURCE CHUNK]
CHUNK_INDEX: 1
START_ID: S001
章节或段落范围：
原文：
...
```

一次最多处理 2500 个中文字符。如果原文跨越章节，在 `locator` 中保留章节名和段落序号。每次分块调用都要指定 `START_ID`，例如第二块从 `S041` 开始，严禁每块都从 `S001` 重新编号。

## 输出格式

先输出一行：

```text
CHAPTER_RANGE: <范围>
```

随后输出 `FACTS_JSONL`。每个叙事事实单元一行，**所有字段必须出现，顺序固定**：

```jsonl
{"source_id":"S001","locator":"第1章第3段","sequence":1,"when":"原文时间或季节；无则写[暂缺]","where":"原文地点；无则写[暂缺]","who":["角色原名"],"event":"一个可观察的因果节拍","change":"结束时具体改变了什么","quotes":[{"speaker":"角色名","text":"逐字台词"}],"motifs":["原文字面出现的意象"],"stage_trap":"最具体的舞台媒介风险；无则写无"}
```

规则：

- 不要逐句切分。按因果节拍提取，通常每 1000 个中文字提取 3–8 条。快速对话若只推动同一个争执或权力变化，合并成一条节拍，`quotes` 可放多条引语；不要把每句台词拆成一条。
- 纯天气、纯气氛和纯背景不单独成条。把其中可复用的意象放进最近一条事实的 `motifs`。
- 一行只能有一个主 `event`，但可以包含同一条因果链内的动作与直接反应。
- 若某个物件或消息直接触发下一步行动，其来源、关键内容和去向必须在同一条 `event` 内写全，不能只写“留下一个信封”而漏掉决定后续的信封内容。
- `source_id` 必须从 `START_ID` 开始连续递增，不跳号、不重复。
- `event` 用 10–80 个中文字描述动作与结果，不写主题解释。写“她把钥匙交给陌生人”，不写“她终于放下了过去”。
- `change` 必须具体到知识、关系、权力、危险、承诺、决定或行动方向，不能为空，也不能写 `[待确认]`。如果原文没有说明，只能写“推断：……”，并确保推断完全由本场行动支撑。
- `when`、`where`、`stage_trap` 无法判断时也要保留字段，分别写 `[暂缺]`、`[暂缺]`、`无`，不得漏键。
- 不得把字段说明抄进值里。例如 `when` 只能写真实时间或 `[暂缺]`，不能写“原文时间或季节；无则写[暂缺]”。
- `quotes` 只收原文直接引语；转述不放进去。`text` 必须逐字复制原文台词，不得为了语法通顺增加“在”“了”等字。
- 原文中每一句由“说、问、答、喊、叫、道”引出的直接对白，都必须在某个事实的 `quotes` 中出现一次；不能因为事件概述里提过就省略原句。
- `motifs` 只收原文字面出现且可能重复使用的物件、声音、颜色或动作。
- `stage_trap` 写最具体的媒介风险，例如“整章只有内心独白”“同一时刻发生在三个城市”。原句含“心里想”“仿佛”“多年后回想”等叙述或内省时，不得写“无”。

JSONL 之后输出：

```text
CONTINUITY_FLAGS
CF01 | <原文矛盾或未解释的空白> | <相关 source_id>
没有问题时只写：NONE

SOURCE_INDEX
S001 | <8–20 字标题> | <事件结果>
S002 | <8–20 字标题> | <事件结果>
必须为每个 FACTS_JSONL 记录提供一行，不得写省略号。

COVERAGE
first_source_id: S###
last_source_id: S###
unparsed_text: 无 / <若有，逐字附上>
```

## 自检

在输出前检查：

1. 所有原文段落是否都已落入某个 `source_id` 或被明确列为 `unparsed_text`？
2. 是否把氛围句逐句拆成了事实，而没有合并成因果节拍？
3. 是否每条都有具体 `change`，且没有把主题解释冒充变化？
4. 是否所有 JSON 对象都包含全部 11 个字段？
5. 是否把叙述者的评价误写成人物事实？
6. 引语是否逐字一致？
7. `SOURCE_INDEX` 是否与 JSONL 行数相同，且每条都有对应行？
8. `first_source_id` 是否等于输入的 `START_ID`，且 `last_source_id` 是否与真实编号连续？

不要输出自检过程，只输出规定结果。
