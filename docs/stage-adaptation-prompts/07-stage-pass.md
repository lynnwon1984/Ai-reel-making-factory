# 当前任务：单场舞台可演性修订

把当前场修到能被演员、导演和舞监实际执行。你只能修正空间、调度、进出场、道具、声音、灯光和兼任冲突；不得改变剧情事实和对白的主要意思。

## 输入

```text
[PROJECT]
...

[STORY BIBLE]
只放舞台世界、转场语法、人物兼任表、母题

[SCENE CARD]
...

[ENTRY STATE]
人物位置 / 关键道具 / 上一场结束状态

[DIALOGUE-PASSED SCENE]
...
```

## 检查表

1. 开场时在场人物与上一场结束状态是否一致？
2. 每个人物的进出场是否有可见原因和足够时间？
3. 同一兼任演员是否被要求同时出现在两个位置？
4. 道具是否在人物手上、身上或可合理拿到的地方？用完后去了哪里？
5. 空间关系是否清楚：谁掌握门、出口、光源、桌面或关键物件？
6. 动作是否能被观众看见，而不是角色脑内发生？
7. 灯光、声音是否承担必要信息？如果只是装饰，删掉。
8. 场景切换是否遵守制作参数中的转场语法？
9. 是否存在镜头词、剪辑词、抽象导演评论或不适用于棚外的效果？
10. 本场结束时，人物、关系、关键道具和秘密是否处于下一场可接管的状态？

## 修订原则

- 抽象心理尽量转成可执行动作：停手、关门、收起证物、换座、避开目光、递出物件、打断对方。
- 不为了“更有戏”增加新事件。只允许细化已有事件的具体执行。
- 不把每句话都配一个动作。动作只改变关系、信息、风险或节奏。
- 关键道具第一次出现时必须有来源，此后必须有去向。
- 同步动作可用 `[同时]` 标记；不要用多栏排版制造无法判断的先后。
- 音乐和音效写“从何处来、何时起、何时停、改变什么”；不要写“悲伤的音乐响起”。

## 输出格式

只输出完整修订场，格式与输入场一致，并在最后一行写：

```text
STAGE_PASS: DONE
```

如果制作参数不足，不能自行假设舞台硬件。保留原调度，并在该处写 `[STAGE FLAG: 需确认...]`。
