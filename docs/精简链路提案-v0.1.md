# 精简链路提案 v0.1

日期：2026-11-20
背景：分镜环节的链路越叠越重（导演提示单 → 6 段分块 → 镜头计划 → 定点修复 → 合并 → 再修）。
本文回答一个问题：**这些复杂度换来了什么，哪些可以砍掉。**

---

## 一、先看数据：复杂度买到了什么

同一批真实模型输出，用**当前规则**重跑一遍：

### 链路质量

| 场景 | 稳定链路（一次出稿） | 实验引擎（导演 schema + 分块 + 修复） |
| --- | --- | --- |
| 5-1 对白 | 13 分镜 · 0 问题 | 17 分镜 · 0 问题 |
| 4-2 动作 | 12 分镜 · 1 高危（伪台词，normalize 后归零） | 21 分镜 · 0 问题 |
| 8-1 多人 | 3 分镜 · 0 问题 | 5 分镜 · 0 问题 |

### 成本

| 项 | 稳定链路 | 实验引擎 |
| --- | ---: | ---: |
| 三场合计 token | 57,053 | 342,698 |
| 倍数 | 1.0× | **6.0×** |
| 修复调用占 token | — | 43%–54% |

**结论：稳定链路本身已经能出 0 问题的稿子；实验引擎多花 6 倍 token，买到的是更细的结构，不是更少的缺陷。**

## 二、skill 收窄：只留 3 条

对照 `visual-skills` 与 `drama-skills`（调研见 `开源导演技能对照与吸收建议-v0.1.md`），只保留这三条：

| 保留 | 理由 | 落地形态 |
| --- | --- | --- |
| **起点 → 唯一变化 → 终点** | 跨镜连续性最直接的抓手 | `src/state-chain.js`：用现成的「人物空间位置」行做相邻比对 |
| **运镜必须说明为什么动** | 直接决定 Seedance 能不能执行 | 已落在分镜正文（CAMERA 行写清镜头怎么动、为什么动） |
| **场景地理 / 轴线** | 正反打不跳轴、多人场不乱 | 已落在「人物空间位置」行 |

### 砍掉的部分

| 砍掉 | 原因 |
| --- | --- |
| 14 字段导演镜头卡 | token 大户，且与现有 shot 字段大量重叠 |
| 每场 6 段分块 + 逐段镜头计划 | 切碎了整场的节奏判断，是 6 倍成本的主因 |
| 多轮整块定点修复 | 修复调用占 43%–54% token |
| 独立资产 manifest | v0.6 已判定不归本流水线 |

**不删代码**：实验引擎保留为显式开关，只退出默认路径。

## 三、方案 A：用现有「人物空间位置」做状态链检查

### 为什么可行

稳定链路每个 shot 都自带一行「人物空间位置」，三场覆盖率 **100%**（13/13、12/12、3/3）。

而这条线的语义是明确的：

> **开镜状态写在「人物空间位置」，状态变化写在 Clip 的 visualAction 里。**

例：

```text
【分镜06】
人物空间位置：亚瑟坐在床沿，端着碗。罗莎琳德躺在床上，看着亚瑟。
Clip A：亚瑟把碗和木勺放到床头柜上，直起身。   ← 状态变化在这里
Clip B：亚瑟站在床边，看着罗莎琳德……

【分镜07】
人物空间位置：亚瑟站在床右侧，面朝罗莎琳德。   ← 与上一镜结尾一致
```

所以可以零成本核对：**上一镜开镜状态 + 上一镜内的变化 == 本镜开镜状态**。

### 检查什么

| 规则 | 判定 | 级别 |
| --- | --- | --- |
| 状态跳变 | 姿势（躺/坐/站/跪/蹲/卧/趴/弯腰）前后不同，但两镜内都找不到过渡动作 | 中 |
| 朝向跳变 | 「面朝/面向」的对象变了，但两镜内找不到转身动作 | 低 |

**只做能确定判定的两件事。** 语义改写、情绪、镜头语言不碰——宁可漏报，不做误报。

### 实现

`src/state-chain.js`

- `parseStateShots(markdown)`：拆 shot / 人物表 / 空间位置 / 可见动作
- `auditStateChain(markdown)`：输出与 QC 同结构的问题列表

已接入 `StoryboardFlow`：与 `runEngineQc` 的结果合并展示，不阻断交付（只出中/低风险）。

### 验证

**真实稿零误报**：

| 场景 | 检查结果 |
| --- | --- |
| 5-1 稳定稿 | 0 条 |
| 4-2 稳定稿 | 0 条 |
| 8-1 稳定稿 | 0 条 |

**合成用例能抓真问题**（`tests/state-chain.test.mjs`，8 条）：

- 坐→站无过渡 → 报中风险
- 坐→站有「直起身」→ 不报
- 蹲→站属允许组合 → 不报
- 面朝 A→面朝 B 无转身 → 报低风险
- 有「转身」→ 不报
- 「面朝乙」vs「面朝右侧的乙」→ 不报（方位归一化）
- 「面朝右侧的乙」里的乙不被当成主语 → 不报

全量单测 **276 条全绿**。

## 四、目标链路

```text
整场 → 一次出分镜（现有稳定链路）
     → 本地 3 条检查（零 token）
        ① 源覆盖   ② 内容预算   ③ 状态链
     → 只有检查失败的 shot 才调模型，且只发那一镜
```

| 项 | 现状 | 目标 |
| --- | ---: | ---: |
| token | 6.0× | 1.2–1.5× |
| 模型调用次数 | 每场 12+ 次 | 每场 1 次 + 失败镜重试 |
| 状态链检查 | 无 | 有（零成本） |

---

## 五、还没做的

1. **自动定点重试**：状态链报出的镜，目前只报告、不会自动重发请求。
2. **源覆盖的单元级回填**：`inferClipReferences` 仍是整块精确匹配，未降到动作微单元。
3. **实验引擎的开关位置**：仍留在页面，但已不是默认路径，需要在 UI 上明确标注"实验"。
