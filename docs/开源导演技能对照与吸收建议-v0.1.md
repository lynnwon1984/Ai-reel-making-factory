# 开源导演技能对照与吸收建议 v0.1

日期：2026-11-05

## 结论先行

这次对照了两个不同路线的开源技能包：

1. `visual-skills/video`：强在导演思维、戏剧节拍、运镜动机、镜头卡和成片节奏。
2. `drama-skills`：强在中文短剧的镜头职责、空间连续性、资产分层、对白估时和机械校验。

它们值得吸收，但不适合整包安装后直接替代现有分镜引擎。

当前项目最合适的方向仍然是：

```text
本地拆场与源块
→ 大模型输出“导演判断 + 结构化镜头计划”
→ 本地校验、回填台词、修时长、查连续性
→ 编译成中文分镜稿和 EOS 交付包
```

最值得补的不是更多形容词，而是四个结构：

- 先写整场导演提示单，再排镜头。
- 每个镜头有明确职责、起点、状态变化和终点。
- 运镜必须说明为什么动，或者为什么不动。
- 人物、造型、道具和场景分身份、版本、镜头瞬态三层管理。

## 我们现在的底座

现有规则引擎已经具备继续吸收这些方法的基础：

- 从标准剧本中拆出集、场和源块。
- 大模型只输出结构化镜头计划，不直接返回最终 Markdown。
- 每个 shot 有本级人物、道具和开场空间状态。
- 每个 Clip 有源块引用、时长、景别、运镜和可见动作。
- 本地回填台词，不让模型重写原文。
- 本地校验源块覆盖、重复引用、对白说话人、宽景对白、内容预算和时长。
- 本地修复人物别名、过载时长和超长 shot。
- 在完整 shot 边界做动态规划，决定分集，不删除原内容。
- 确定性生成正文分镜、EOS 文本、镜头总表和交付包。

当前短板也很明确：

- 没有整场导演提示单。
- shot 只有开场位置，没有明确的结束状态。
- 没有“本镜职责”和“为什么用这个运镜”的结构字段。
- 没有相邻镜头状态连续性的自动核对。
- 道具目前基本是名字列表，没有持有人、手、开合、内容物和有效范围。
- 人物目前区分了出场人物和着装，但没有“基础身份 / 造型版本 / 镜头瞬态”的层级。
- 内容审核仍以预算和格式为主，导演质量还主要靠人工看稿。

## 两套技能分别解决什么

| 能力 | visual-skills | drama-skills | 对本项目的判断 |
| --- | --- | --- | --- |
| 整场戏剧判断 | 很强：欲望、阻碍、空间、注视和节奏 | 强：戏型诊断、权力转移和观众知情 | 吸收 |
| 镜头职责 | 每镜必须改变情绪、推进动作或增加压力 | 每镜必须有唯一职责和来源 | 吸收，做成本地可校验字段 |
| 运镜动机 | 每镜回答“画面发生了什么变化” | 逐镜写行为、起止和理由，固定也要有理由 | 高优先级吸收 |
| 起止状态 | 强调最终画面 | 明确“起点 → 唯一动作 → 终点” | 高优先级吸收 |
| 动作连续性 | 有物理后果和动作链方法 | 有动作落实表、左右手和持物交接 | 吸收，补进镜头计划和校验器 |
| 场景地理/轴线 | 有空间几何和权力站位 | 有场景锚点、working side、正反打和越轴记录 | 吸收，并按 9:16 竖屏重新表述 |
| 资产分层 | 有身份锚点 | 明确区分身份、造型版本和镜头瞬态 | 吸收成内部资产账，不接管制作工具 |
| 对白估时 | 有时长纪律 | 先排完整声音事件，再决定镜长 | 吸收，继续由本地估时 |
| 节奏 | 三幕式节拍、节奏阶梯 | 对白覆盖和镜头密度 | 只作为 craft default，不设机械配额 |
| Seedance 2.5 | 有完整生产参考 | 有中文的时间戳、容器和参考素材语法 | 以官方 `sd25-pe` 为准，二者只作补证 |
| EOS 交付 | 不负责 | 不负责 | 继续使用本项目现有 EOS 适配 |
| 固定关键帧与图片绑定 | 有 | 很完整 | 不进入本项目产品范围 |

## 可以直接吸收的内容

### 1. 整场导演提示单

在镜头计划前增加一份场景级《导演提示单》，由模型输出，本地校验完整性。

建议最小字段：

```json
{
  "sceneId": "1-1",
  "dramaticQuestion": "这场戏围绕什么问题展开",
  "desire": "当前主行动者想要什么",
  "obstacle": "谁或什么阻止他",
  "powerBefore": "开场谁掌握空间、信息或选择权",
  "powerAfter": "结尾权力如何变化",
  "informationReveal": "观众在第几拍得知什么",
  "visualCore": "本场必须成立的视觉核心",
  "keyProp": "承担叙事故能的道具及其状态",
  "startHook": "开场抓人的事实或压力",
  "endHook": "结尾留下的新问题或未完成动作"
}
```

作用：

- 先确定整场如何变化，再让模型排镜头。
- 防止每个镜头都对，但整场没有戏。
- 让后续审查能判断镜头是否真的服务本场。

### 2. 精简版导演镜头卡

不建议把 `visual-skills` 的 14 个字段原样塞进现有 JSON。现有链路已经有源块、台词回填和时长裁决，再增加太多字段会显著提高 token 和漂移。

建议在现有 shot 结构上补这些字段：

```json
{
  "purpose": "本镜唯一职责",
  "storyFunction": "establish | power | pressure | detail | reaction | shift | impact | aftermath | exit",
  "startState": "人物、双手、持物、朝向、位置、空间关系",
  "stateChange": "本镜唯一主要状态变化",
  "endState": "动作结束后可被下一镜继承的事实",
  "cameraReason": "为什么推、跟、摇、固定",
  "soundCue": "本镜必须听见的声音事件；无则写无",
  "continuityNote": "本镜必须保持的身份、造型、道具或空间事实"
}
```

Clip 结构继续保留：

```json
{
  "duration": 5,
  "size": "MCU",
  "cameraMove": "固定机位",
  "visualAction": "可见动作",
  "sourceBlockIds": ["B07", "B08"]
}
```

这样既不推翻现有实验引擎，也能把导演判断变成可检查的数据。

### 3. “起点 → 唯一变化 → 终点”状态链

这是本次对照中收益最高的一项。

现有计划只有 `startPosition`，下一镜是否接得上主要靠模型自觉。吸收 `drama-skills` 后，应做到：

- 每镜明确起点：位置、朝向、视线、左右手、持物和关键空间关系。
- 每镜只声明一个主要状态变化。
- 每镜明确终点：变化后的事实。
- 下一镜的起点必须能追溯到上一镜的终点。
- 同一个动作默认只由一个主镜头完成；反应镜和细节镜不重复执行动作。
- 峰值处确实需要冲击重复时，必须显式声明。

这项可以直接进入本地校验，是最有价值的确定性能力。

### 4. 运镜理由

每个镜头必须回答一个问题：

> 摄影机为什么在这里动，或者为什么不动？

可接受的理由包括：

- 新信息进入画面。
- 人物的决定改变了关系。
- 压力升高，画面收紧。
- 人物看向某处，镜头揭示他看到什么。
- 动作发生位移，需要跟住主体。
- 空间本身改变了，例如门打开或人物进入。
- 本镜选择固定，是为了让观众观察、等待、看清证据或保持压迫。

不吸收“每镜必须运动”，也不吸收“某种运镜只能用于某种情绪”的死规则。关键是理由成立。

### 5. 资产三层模型

吸收 `drama-skills` 的三层判断，但只做内部账本，不接管实际图片和制作工具：

| 层级 | 本项目的含义 | 示例 |
| --- | --- | --- |
| 持续身份 | 全剧必须认出是同一个对象 | 人物、地点、关键道具 |
| 版本/状态 | 有来源、有有效范围的持续变化 | 换装、受伤、染血、道具破损、停电 |
| 镜头瞬态 | 只在本镜成立，不能沉淀成新版本 | 抬手、转头、短暂遮挡、画面左右位置 |

建议建立三个内部表：

- `castLedger`：角色身份、别名、首次出场、造型版本。
- `propLedger`：道具身份、首次出现名称、持有人、左右手、开合、内容物、状态变化。
- `sceneLedger`：地点身份、固定锚点、入口出口、天气、时段、光态和观察方向。

输出时每镜只引用本镜实际可见或实际变化的条目，禁止整场资产污染所有镜头。

### 6. 连续性锁，但只锁“最小可辨识事实”

连续性锁不写成剧情长句，也不写成“高质量、电影感”这类无效词。

建议使用最小名词短语，例如：

```text
人物：银白胸甲、深蓝披风
道具：带缺口的黑铁匕首
场景：北侧高台、双开木门、沙地中央
状态：右肩箭伤，自 1-3 持续至 1-5
```

本地校验器负责判断：

- 同一实体是否有多个名字。
- 同一场未经来源动作是否换装或换手。
- 道具是否在镜头之间瞬移。
- 角色是否无来源改变伤势、污损、开合或内容物。
- 连续性锁在本应生效的镜头里是否消失。

### 7. 场景站位与轴线

吸收 `drama-skills` 的“先锁空间锚点，再设计镜头”：

- 场景固定锚点：门、桌、王座、台阶、出口、证据位置。
- 人物相对锚点的关系。
- 主轴线和工作侧。
- 谁能看见、接近或控制什么。
- 哪一镜改变站位。
- 正反打时，视线方向和画面方向必须互补。
- 越轴必须有新的空间地图或明确过渡。

本项目是 9:16 竖屏，因此可以吸收竖屏的前后景压缩、纵向空间、人物占幅和多人主镜头后再切近景的方法；平台特定的顶部/侧边控件避让仍需等拿到明确交付模板后再启用。

### 8. 对白覆盖与听者反应

采用它的“先排声音，再定镜长”方法，但不硬套固定句数。

- 每句台词必须整体进入声音时间线。
- 有实际配音时用实际发声区间。
- 没有配音时，按语速、停顿和情绪做文本估计，并明确标记“估算”。
- 台词较长时，允许声音连续、画面切换；不得要求角色加速念完。
- 重要信息落下后，检查是否给听者一个可见处理。
- 既无台词、无动作、无信息也无压力的空镜应合并或删除。

现有本地 `dialogueCps`、`dialogueWps` 和停顿规则可以继续使用，后续再拿真实录音和生成结果校准。

### 9. 关键镜头覆盖方案比较

`Coverage Audition` 不用于所有普通场景，只在关键场次启用。

可比较的五种方案：

- 表演中心：先看人物如何承受信息。
- 证据中心：先看关键物件，再看接收者。
- 主观错位：中途改变观众站在谁的一侧。
- 空间中心：用入口、距离和阻挡完成权力转移。
- 声音中心：先让画外声改变压力，再给画面确认。

用途是给关键场提供真正的导演选择，不是让模型每场都输出五套方案。

## 不建议照搬的内容

### 1. 不整包装进产品

`drama-skills` 是完整的“剧本 → 资产 → 图片提示词 → 分镜 → 视频提示词 → 生产 → 审查”套件。本项目的正式边界是交付分镜剧本，资产、图片、视频和 EOS 后续操作由制作人员负责。

如果整套接入，产品会从“剧本清洗与分镜流水线”膨胀成完整制片平台，偏离当前设计。

### 2. 不接管图片、关键帧和 `REF/PLAN/IMG` 体系

这些体系很适合制作端，但不应该成为本产品的前置条件。

本项目可以采用资产账本和连续性要求，但不要求：

- 每镜有冻结关键帧。
- 每镜绑定真实参考图。
- 用户维护图片提示词条目。
- 角色必须在当前产品里选图。

### 3. 竖屏规则要分“创作方法”和“平台安全区”

源技能里不少多人调度、人物占幅和近景组织规则适合本项目竖屏使用。

平台特定的顶部安全区、侧边互动控件和字幕区不能直接当永久规则；只有拿到当前交付模板时才启用。

### 4. 不采用英文 Prompt 默认规则

`visual-skills` 默认最终 Prompt 用英文，以适应部分视频模型。本项目当前要求用户可见分镜和 Seedance 2.5 编写以中文为主，原创英文台词保留原文。

因此只吸收导演结构，不照搬语言策略。

### 5. 不把“每镜三细节”设成硬门禁

“环境压力 + 身体微动作 + 声音/视觉母题”是很好的审查提醒，但不应强制每个镜头都塞满三项。

- 一个关键道具特写可能不需要再写环境压力。
- 一个刻意静止的等待镜头可能就是有效选择。
- 为了通过字段而硬加雨、风声或手指动作，会制造新问题。

建议将三项设为 `craft_default` 和人工审查提示，不做格式阻断。

### 6. 不照搬固定节奏和平均镜长

节奏阶梯、每秒切镜和“平均镜长”不能成为全剧统一配额。

现有项目的时长基础更可靠：

- 流程二提供故事内容估时。
- 分镜引擎根据对白和动作负载计算 Clip 时长。
- 集边界由动态规划裁决。

开源方法用于解释“为什么这个镜头值得存在”，不用于覆盖本地预算器。

### 7. 不让模型直接写最终整稿

两套技能只要交给大模型，都可能再次回到“一次生成长 Markdown”。本项目的关键优势是 JSON 计划、源块引用和确定性编译，不能放弃。

## 推荐最小改造

### P0：提升导演判断，不改产品边界

1. 镜头计划新增：
   - `purpose`
   - `storyFunction`
   - `startState`
   - `stateChange`
   - `endState`
   - `cameraReason`
   - `continuityNote`
2. 场景计划新增：
   - `directorBrief`
   - `sceneGeography`
3. 本地校验新增：
   - 职责不能为空。
   - 运镜理由不能为空。
   - 起点与终点不能相同。
   - 相邻镜头状态需能衔接，或在计划中声明时间/空间跳跃。
   - 每个源块仍有且仅有一次主落实。
   - 人物和道具只能引用本场已登记资产。
4. 保持现有：
   - 源块引用。
   - 台词回填。
   - 时长预算和裁决。
   - EOS 和 ZIP 交付。

### P1：资产账与连续性

1. 建立三类内部账本：
   - 人物身份与造型版本。
   - 道具身份与状态变化。
   - 场景地理与观察方向。
2. 区分持续状态和镜头瞬态。
3. 每镜记录实际受影响的资产，禁止全场资产污染。
4. 对换装、伤势、持物、开合和道具转手做定向回查。

### P2：质量辅助，不影响稳定交付

1. 关键场启用覆盖方案比较。
2. 增加“导演审查”视图：
   - 本场是否完成权力或信息变化。
   - 哪些镜头只是复述句子。
   - 哪些切点没有带来新信息、压力、关系或空间变化。
   - 哪些重要台词没有落出听者反应。
   - 哪些运镜与人物动作争夺注意力。
3. 建立人工评分样本，不把模型自评当成质量结论。

## 最终取舍

建议吸收：

- 整场导演提示单。
- 每镜职责。
- 运镜动机。
- 起点、状态变化、终点。
- 场景空间锚点与轴线。
- 人物/造型/道具的身份、版本、瞬态分层。
- 对白先排声音再定时长。
- 关键场覆盖方案比较。

建议只作审查方法：

- 每镜三细节。
- 节奏阶梯。
- 五锚点。
- Murch Rule of Six。

建议不进入当前产品：

- 完整 12 技能制片流水线。
- 图片和视频生成。
- 冻结关键帧生产。
- `IMG/PLAN/REF` 资产图片体系。
- 未确认平台模板前的固定顶部/侧边安全区。
- 英文 Prompt 默认策略。

## 下一步建议

先不改流程三页面，也不接开源技能运行。

下一步应拿 `docs/云端分镜引擎实验-v0.1.md` 已有的 62 源块样本，按新增字段做一份 JSON schema 草案和一条离线回放，验证：

- 新增字段会不会显著增加 token。
- 现有模型能否稳定填满职责、运镜理由和起止状态。
- 相邻状态能否用本地规则检查。
- 新的镜头计划是否比现有结果更接近“优秀导演思维”。

只有这三项通过，才值得进入页面和正式流程。
